# AGENTS.md

## Назначение проекта

`D:\code\333` — статический персональный сайт `evgenbond.ru` с портфолио,
описанием услуг и блогом.

Цель изменений — сохранять сайт простым, быстрым и предсказуемым без
необязательных фреймворков, backend и базы данных.

## Текущая архитектура

- Главная страница: `index.html` с локальными HTML и CSS.
- Блог: Markdown-файлы в `content/blog/*.md`.
- Изображения блога: `assets/blog/`.
- CMS: Pages CMS, схема хранится в `.pages.yml`.
- Вход в CMS: `admin/index.html`.
- Генератор: `scripts/build-blog.mjs`.
- Результат сборки: `_site/`.
- Публикация: GitHub Pages через `.github/workflows/pages.yml`.
- Домен: `evgenbond.ru`, конфигурация в `CNAME`.
- Runtime backend и база данных отсутствуют.

Поток данных блога:

`content/blog/*.md` → парсинг и валидация → HTML-шаблоны → `_site/blog/`.

## Основные документы

- `docs/PROJECT_STATE.md` — текущее состояние и ближайшие задачи.
- `docs/BLOG_CMS.md` — устройство блога и инструкция по Pages CMS.

Не ссылаться на отсутствующие документы и каталоги как на обязательные.

## Правила изменений

- Сначала прочитать релевантный код и документацию.
- Вносить только минимальные изменения, необходимые для задачи.
- Не проводить несвязанные рефакторинги и не менять дизайн без запроса.
- Не добавлять зависимости без явной технической причины.
- Не внедрять Next.js, Go, PostgreSQL, shadcn или другую новую платформу,
  если пользователь отдельно не запросил миграцию.
- Сохранять обратную совместимость URL и структуры контента.
- Сохранять адаптивность главной, блога и статей.
- Поддерживать текстовые файлы в UTF-8.
- Не перезаписывать и не откатывать пользовательские изменения.

## Дизайн

- Сохранять текущий строгий модульный стиль.
- Основная палитра: белый, чёрный, светло-серый и красный акцент.
- Основной шрифт: `Inter Tight`.
- Моноширинные элементы: `JetBrains Mono`.
- Характерные элементы: сетка, строгие границы, крупная типографика,
  прямоугольные кнопки и минимальная анимация.
- При изменении интерфейса проверять desktop и mobile.

## Блог и CMS

- Новые статьи создавать в `content/blog/`.
- Структуру полей CMS синхронизировать с валидацией генератора.
- Не публиковать статью без обязательных метаданных и контента.
- Для новой статьи обязательны корректные `title`, `slug`, `date`,
  `description`, `coverImage`, `sharedImage` и соответствующие alt-тексты.
- `slug` должен содержать только латинские буквы, цифры и дефисы.
- `coverImage` используется в карточке и опционально внутри статьи.
- `sharedImage` используется только для Open Graph и Twitter.
- Пользовательский Markdown необходимо пропускать через sanitization.
- Для внешнего видео разрешать только проверенные HTTPS embed URL.
- Не коммитить `_site/`: он создаётся сборкой и публикуется GitHub Actions.

## Проверка и деплой

- После завершения правок агент самостоятельно запускает обязательную
  автоматическую проверку:

```powershell
npm run build
```

- Для интерфейсных изменений агент по возможности самостоятельно выполняет
  браузерную smoke-проверку desktop и mobile.
- Не требовать от пользователя локальной проверки.
- После успешных проверок сразу закоммитить изменения и отправить `main` в
  `origin`, если пользователь явно не запретил деплой.
- Push в `main` запускает публикацию через GitHub Actions и GitHub Pages.
- После push проверить завершение workflow и доступность изменённой страницы
  на `https://evgenbond.ru/`.
- Если проверка, push или деплой завершились ошибкой, не считать задачу
  выполненной: диагностировать проблему и сообщить точную причину.

## Git и локальные файлы

- Перед изменениями и после них проверять `git status --short`.
- По умолчанию коммитить и деплоить проверенные изменения сразу после
  завершения задачи.
- Не коммитить и не деплоить только при прямом запрете пользователя.
- Не коммитить `node_modules/`, `_site/`, `.env*`, `.vscode/sftp.json`,
  `*.completed.csv`, `*.backup.html`, логи и локальные служебные файлы.
- Если Pages CMS создал удалённый commit параллельно локальной работе,
  перед push синхронизировать ветку без потери локальных изменений.
