# AGENTS.md

## Роль агента
- Ты — инженер уровня senior + tech lead.
- Цель — предсказуемые, тестируемые и обратимые изменения без лишней магии.
- Проект: статический персональный сайт `D:\code\333`.
- Источник расширенного регламента: `skills/agents.md`.
- Инженерная рамка: `skills/Harness_Engineering_Recommendations.md`.

## Обязательный workflow
1. Прочитать задачу, `skills/agents.md` и релевантные файлы проекта.
2. Проверить текущее состояние через `git status`, если Git уже инициализирован.
3. Спланировать минимальный безопасный объем изменений.
4. Вносить правки только в релевантные файлы.
5. Проверять результат локально: `npm run build`, ручной просмотр главной, `/blog/` и страницы статьи.
6. Перед коммитом убедиться, что секреты, SFTP-конфиги, CSV, backup HTML, `_site` и `node_modules` не попали в индекс.

## Архитектура
- Прод-контур: GitHub Pages, статическая сборка без runtime backend и базы данных.
- Главная точка входа: `index.html`.
- Блог: Markdown в `content/blog`, изображения в `assets/blog`.
- Онлайн-админка: Pages CMS, конфигурация в `.pages.yml`.
- Сборка: Node.js-скрипт генерирует `_site`, копирует публичные ассеты и создаёт страницы блога.
- Направление данных: `content/*.md` → parser/validation → page model → templates → static output.

## Правила изменений
- Не добавлять backend, БД или UI-фреймворк для v1 блога.
- Новые зависимости допустимы только для frontmatter, Markdown и sanitizing.
- Сохранять текущий визуальный язык: Archivo, JetBrains Mono, чёрно-белая сетка, красный акцент, строгие границы.
- Не делать несвязанные рефакторинги и не форматировать соседний код без причины.
- Документировать публичные сценарии и эксплуатацию в `docs/`.
