# Blog CMS

## Как устроено
- Статьи лежат в `content/blog/*.md`.
- Картинки для статей и shared links лежат в `assets/blog` или в корне сайта, если это общий файл вроде `/sharedlink.jpg`.
- Файлы для скачивания из статей лежат в `assets/downloads`.
- Онлайн-редактор: Pages CMS, конфигурация в `.pages.yml`.
- Публикация: `npm run build` собирает статический сайт в `_site`.
- GitHub Pages публикует `_site` через workflow `.github/workflows/pages.yml`.
- Дизайн блога: компактная журнальная сетка карточек и блочная статья без большого hero.

## Главные файлы
- `.pages.yml` - схема админки Pages CMS.
- `scripts/build-blog.mjs` - короткая точка запуска генератора.
- `scripts/blog/content.mjs` - чтение и валидация статей.
- `scripts/blog/render.mjs` - HTML-шаблоны блога и статей.
- `scripts/blog/seo.mjs` - `robots.txt`, `sitemap.xml` и SEO-данные.
- `scripts/blog/build-site.mjs` - сборка файлов в `_site`.
- `content/blog/2026-06-01-blog-start.md` - пример статьи.
- `admin/index.html` - входная страница для онлайн-админки.
- `docs/PROJECT_STATE.md` - быстрый контекст проекта и следующие шаги.
- `skills/agents.md` - единственный агентский регламент проекта.

## Поля статьи
- `title` - заголовок страницы и shared link.
- `slug` - URL вида `/blog/<slug>/`, только латиница, цифры и дефисы.
- `date` - дата публикации.
- `published` - если `false`, статья не попадает в сборку.
- `description` - SEO и shared-link описание.
- `coverImage` - видимая обложка карточки в сетке блога; рекомендуемый размер 1200x630 px.
- `coverImageAlt` - alt-текст видимой обложки.
- `showCoverInArticle` - показывает или скрывает `coverImage` в начале статьи.
- `showCoverBorder` - показывает или скрывает рамку вокруг обложки внутри статьи.
- `sharedImage` - картинка только для shared-link сниппетов, например `/assets/blog/post-share.jpg`; в теле статьи не выводится.
- `sharedImageAlt` - alt-текст shared-link картинки.
- `tags` - список тегов; генератор автоматически создаёт публичные страницы вида `/blog/tag/sayty/`, а теги в карточках и статьях становятся ссылками.
- `blocks` - блочный конструктор статьи.

## Блоки статьи
- `text` - Markdown/Rich text блок для абзацев, заголовков, списков и ссылок.
- `image` - отдельная картинка между текстовыми блоками; поля: `image`, `alt`, `caption`, `showBorder`, параметры рамки, скругление и `size`. В статье картинки выводятся целиком, сохраняют исходные пропорции и открываются на весь экран по клику.
- `video` - адаптивный embed YouTube, Kinescope или другого HTTPS-плеера; поля: `provider`, `url`, `title`, `caption`, `size`. Плеер выводится в светлой рамке со скруглёнными углами. Вставлять нужно ссылку на видео или embed URL, не iframe-код.
- `code` - блок кода с кнопкой копирования; поля: `language`, `caption`, `code`.
- `quote` - цитата; поля: `text`, `author`.
- `divider` - визуальный разделитель с необязательной подписью.
- `download` - карточка файла для скачивания; поля: `file`, `title`, `description`. Формат и размер определяются автоматически.

### Файлы для скачивания
- Документы: `pdf`, `doc`, `docx`, `rtf`, `odt`.
- Таблицы: `xls`, `xlsx`, `ods`, `csv`.
- Презентации: `ppt`, `pptx`, `odp`.
- Текст и данные: `txt`, `md`, `html`, `htm`, `json`, `xml`.
- Архивы: только `zip`.
- Максимальный размер одного файла — 20 МБ.
- Исполняемые файлы и документы Office с макросами (`docm`, `xlsm`, `pptm`) запрещены.
- HTML, ZIP и старые форматы Office публикуются только из доверенных собственных источников. HTML-файл по прямому URL является активной страницей сайта, а содержимое ZIP сборка не проверяет.

Старый формат с Markdown в `body` поддерживается генератором как fallback, но новые статьи лучше вести через `blocks`.
Демо-статьи в `content/blog` опубликованы только для проверки плотной сетки; перед финальной редактурой их можно заменить реальными материалами или снять с публикации через `published: false`.
Пагинация блога включается автоматически, когда опубликованных статей становится больше 6: первая страница остаётся `/blog/`, следующие создаются как `/blog/page/2/`, `/blog/page/3/` и дальше.

## Изображения и автоматическая оптимизация
- CMS принимает `jpg`, `jpeg`, `png` и `webp` в `assets/blog`.
- Во время сборки Sharp автоматически создаёт WebP-варианты JPEG и PNG с качеством 86 и ограничением 1600 px по длинной стороне без увеличения маленьких изображений.
- Оригинал сохраняется в репозитории и используется как fallback. Сгенерированные WebP находятся только в `_site` и не коммитятся.
- `sharedImage` для Open Graph остаётся в исходном JPEG/PNG/WebP для совместимости мессенджеров и соцсетей.
- Не стоит загружать заведомо огромные исходники: автоматическая оптимизация ускоряет сайт, но исходный файл всё равно увеличивает Git-репозиторий и резервные копии.

## Вставка картинки из буфера
1. Добавить или открыть блок `text`.
2. Переключиться в режим `Editor`, если открыт исходный Markdown.
3. Скопировать изображение или сделать скриншот в буфер обмена.
4. Нажать `Ctrl+V` в нужном месте текста.
5. Pages CMS загрузит файл в `assets/blog` со случайным безопасным именем и добавит ссылку в Markdown.

Вставка из буфера поддерживается самой Pages CMS только внутри rich-text редактора. В отдельном поле `image` остаются выбор из медиатеки и обычный upload. Для индивидуальной рамки, цвета и скругления нужно использовать отдельный блок `image`.

## Оформление изображений
- `Показывать рамку` включает или отключает рамку, не отключая скругление.
- `Толщина рамки` — от 1 до 12 px.
- `Стиль рамки` — сплошной, пунктирный, точечный или двойной.
- `Цвет рамки` задаётся HEX-кодом, например `#C80000`.
- `Скругление` — от 0 до 64 px.
- Такие же параметры доступны для обложки статьи.
- Hosted Pages CMS не предоставляет встроенный color-picker для произвольного цвета, поэтому используется валидируемое HEX-поле.

## Локальная проверка
```powershell
npm install
npm run build
npm test
npm run check
npm run dev
```

После запуска `npm run dev` открыть:
- `http://localhost:4173/`
- `http://localhost:4173/blog/`
- `http://localhost:4173/blog/zachem-biznesu-sistemnyy-sayt/`
- `http://localhost:4173/admin/`

Видео-блоки не меняют `sharedImage`: картинка для сниппетов по-прежнему задаётся отдельным полем `sharedImage`.
Обложка и изображения внутри статьи открываются в полноэкранном просмотре по клику. Просмотр закрывается кнопкой, кликом по фону или клавишей `Esc`.

## Как добавить статью через Pages CMS
1. Открыть `https://app.pagescms.org/`.
2. Войти через GitHub.
3. Выбрать репозиторий `Nefedorb/evgenbond-site`.
4. Открыть коллекцию `Блог`.
5. Создать статью, заполнить обязательные поля, загрузить `coverImage` и `sharedImage`.
6. Собрать материал из блоков: чередовать `text`, `image`, `video`, `quote`, `code`, `download` и `divider` в нужном порядке.
7. Сохранение в CMS создаёт commit в GitHub; после этого GitHub Actions пересобирает сайт.

## Ограничения v1
- Нет runtime backend и базы данных.
- UI-фреймворки не используются.
- `_site`, `node_modules`, `.vscode/sftp.json`, CSV, backup HTML и локальные артефакты не коммитятся.
- Статья без `title`, `slug`, `date`, `description`, существующего `coverImage`, существующего `sharedImage` или контентных блоков не должна молча попасть в публикацию.
